# 操作モデルとキーボードショートカット

VAR は秒単位で操作する道具で、マウスだけの設計では実運用の速度に追いつかない。
判定要求から映像提示までの時間が競技進行を止めるため、頻用操作はすべて
片手で届くキーに割り当てる。

## 前提

1台1画面でオペレータ1名が兼用する（レビュー操作と配信切替の両方）。
したがって「配信に乗る操作」と「手元で探す操作」を明確に分ける必要がある。

## ショートカット一覧

| キー | 動作 | 意図 |
|---|---|---|
| `1` `2` `3` `4` | 該当カメラを単一全画面表示 | 判定は基本的に1カメラで精密に見る |
| `0` | 4分割表示に戻る | 俯瞰して、どのカメラに写っているかを探す |
| `←` `→` | コマ送り（1フレーム前後） | 接触の瞬間を特定する。VARの核心操作 |
| `Shift` + `←` `→` | 10フレーム前後 | 目的の場面に素早く寄せる |
| `,` `.` | 再生速度をプリセット間で下げる/上げる | スロー⇔実速度の往復。手元を見ずに操作する |
| `K` | 一時停止 / 再開 | 静止画で見せる |
| `Space` | 現在時刻にハイライトタグを打つ | 録画を止めずにその場でマーキング |
| `L` | LIVE に復帰 | リプレイから現在へ即座に戻る |
| `R` | 選択カメラのズーム/パンを解除 | 拡大したまま迷子になるのを防ぐ |

## マウス操作

| 操作 | 動作 |
|---|---|
| ホイール | カーソル位置を中心にズーム（1.0〜16.0倍） |
| ドラッグ | パン（拡大中のみ意味を持つ） |
| クリック | そのカメラを選択（コマ送りの基準カメラになる） |
| ダブルクリック | 単一表示 ⇔ 4分割 のトグル |

## 再生速度のプリセット

`0.1x` `0.25x` `0.5x` `1.0x` `2.0x` `4.0x`（加えてスライダーで 0.05〜4.00x を連続変更）

サッカーVARの運用に倣い、用途を分ける:

- **スロー（0.1〜0.5x）** … 接触点の特定。どこで当たったか
- **実速度（1.0x）** … 反則の強さ・意図性の判断。スローは強度を過大に見せる
- **早送り（2〜4x）** … 目的の場面を探す移動用

この2つを行き来できること自体が要件なので、`,` `.` を隣接キーに置いている。

## 設計上の決定

- **コマ送りは「時刻 + 1/fps」ではなく実フレームを辿る。**
  フレーム落ちがあっても必ず隣の実フレームへ移動でき、
  「送ったのに絵が変わらない」が起きない。実装は `core/timeline.py` の
  `FrameBuffer.step()`。
- **4分割の同期は再生ヘッド時刻に対する最近傍フレームで行う。**
  UVC にハード同期が無い以上これが現実的な最良手。実装は
  `Timeline.frames_at_playhead()`。
- **取得スレッドと再生（描画）は完全に分離。**
  描画は約60Hzのタイマー、取得はカメラごとの専用スレッド。
  両者は `FrameBuffer` だけを介する。再生操作が録画を絶対に止めない。
- **単一表示中は非表示ビューを描画しない。** 無駄なCPUを使わない。
